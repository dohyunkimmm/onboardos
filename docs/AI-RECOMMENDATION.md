# 직무 기반 AI 라이선스 추천

## 사용자 흐름

로그인 후 직군을 선택하면 **추가 텍스트 입력이나 Gemini 동의 없이** 직군 기준 추천 3개를 표시한다. 사용자가 **업무 케이스**를 고르거나 짧은 자연어(예: `PDF`, `디자인 편집`, `AI`)를 입력하면 직군과 관계없이 해당 업무에 적합한 카탈로그 도구 3개를 먼저 보여준다. 최소 5글자 제한은 없다. 선택한 케이스와 자연어가 둘 다 있으면 케이스를 우선한다. 입력은 선택사항이고 최대 길이만 500자로 제한한다.

공통 케이스는 PDF 편집, 디자인 편집, 그래픽 제작, 전자계약, 개발·API, 분석, AI 업무, PM, 협업, 문서 작성 등을 포함한다. 각 직군 전용 케이스도 별도로 제공한다. 예를 들어 **경영지원 + 디자인 편집**에는 Figma가, **디자인 + PDF**에는 Acrobat이 추천될 수 있다. 이때 다른 직군에 기본 배정된 제품은 반드시 **직군 외 · 예외 검토 필요**로 표시하며, 기존 데모 헬프데스크에 개별 요청을 *작성*하도록 연결한다. 자동 지급·권한 승인이나 정상 직군 라이선스 신청으로 연결하지 않는다.

외부 Gemini에 전송하려면 직군, 케이스, 선택적으로 입력한 업무 설명, 카탈로그 목록의 전송에 명시적으로 동의해야 한다. 동의 후에는 1초 입력 지연 뒤 같은 출처 `/api/recommend`으로 요청하며 최대 3개를 반환한다. 동의를 철회해도 로컬 직군·업무 케이스 추천은 계속 이용할 수 있다. 직군·케이스·업무·동의 변경 시 이전 요청은 중단하고 늦게 돌아온 응답은 무시한다. 동의와 업무 입력은 저장하지 않는다. Gemini 오류·제한·후속 질문 상황에는 로컬 기본 추천을 유지한다.

라이선스는 **공통 5개 + 직군 핵심 18개 + 직군별 확장 20개 = 총 43개**이다. 확장 카탈로그는 직군별 다섯 개씩이며 AI·협업툴·PM툴·기타 카테고리를 펼쳐 탐색할 수 있다. 기존 라이선스 검색 및 상태 필터를 확장 도구에도 적용한다. 실제 서비스별 구매 권한·좌석·계정 생성은 구현하지 않았으며, 새 도구의 신청 상태와 SLA는 **프로토타입 가정**이다.

기존 직군 선택 옆 **AI 추천** 수동 모달은 보조 경로로 유지한다. 이 모달도 최소 입력 글자 수 제한 없이 업무 표현에서 공통 케이스를 인식하며, 직군 외 도구는 동일하게 예외 요청으로 연결한다.


## 실행 설정

기존 정적 화면에 Vercel Node.js Function `api/recommend.js`를 추가했다. 브라우저는 같은 출처의 `/api/recommend`만 호출한다. 서버는 `data.js`의 동일한 카탈로그를 직접 읽고 Gemini Generate Content API의 JSON Schema 출력을 검증한다. 별도 패키지 설치는 필요 없다.

서버 환경변수:

| 이름 | 값 |
| --- | --- |
| `GEMINI_API_KEY` | Google AI Studio에서 발급한 Gemini API 키. 프런트엔드에 포함하지 않는다. |
| 모델 | 코드에서 `gemini-3.5-flash-lite`로 고정. 무료 등급 지원 모델이며 유료 모델로 자동 전환하지 않는다. |
| `AI_RECOMMENDATIONS_ENABLED` | 실제 호출을 활성화할 때만 `true` |

기본값은 비활성이다. 설정이 없으면 503을 반환하고 화면에 미연결 안내를 표시한다. 규칙 기반 응답을 AI 결과로 대체하지 않는다. `python -m http.server` 같은 정적 서버에서는 API가 실행되지 않는다. 실제 호출은 Vercel 배포 환경이나 Vercel 로컬 개발 환경에서 검증한다.

이 프로젝트의 Google SSO는 모의 로그인이다. 이 API도 사내 인증이 적용된 서비스가 아니며, 동일 출처 검사는 인증이나 사용량 제한이 아니다. 무료 포트폴리오용으로는 결제 계정을 연결하지 않은 Free Tier 프로젝트의 키를 사용한다. API 키만으로 서버가 결제 등급을 판별할 수 없으므로 Google AI Studio에서 Free Tier임을 확인한다. 유료 등급으로 전환하지 않는다. 무료 호출 한도 초과는 429로 표시하고 자동 재시도나 다른 공급자·모델로의 전환은 하지 않는다. 공개 배포 시 플랫폼 요청 제한도 적용한다. 실제 사내 운영 시에는 서버에서 직원 인증과 직군을 검증해야 한다. 현재 `role`은 체험용 직군 선택값이다.

## 처리 범위와 데이터

- 입력 0~500자(최소 길이 없음), 요청 본문 4KB 제한. 공급자 요청 20초·클라이언트 대기 25초 제한.
- AI에 전달하는 값은 직군 키, 업무 설명(있는 경우), 선택·추론한 업무 케이스, 해당 케이스의 허용 카탈로그뿐이다. 이메일·이름·신청 이력을 전송하지 않는다.
- 입력과 결과를 별도로 저장하거나 분석 이벤트로 수집하지 않는다. 무료 등급에서는 Google이 입력·응답을 제품 개선에 사용할 수 있다. 실제 직원 정보나 회사 기밀을 사용하지 않고 가상 직무 정보로 체험한다.
- 브라우저에서 외부 AI 전송 안내를 먼저 표시한다. API 오류·거절·시간 초과 시 기존 목록을 계속 이용할 수 있다.
- 선택한 업무 케이스·직군 카탈로그 범위 바깥의 ID, 중복 라이선스, 잘못된 형식, 미완료 응답은 거부한다. 명시된 업무 케이스가 허용하는 직군 외 도구는 반드시 예외 검토로 표시한다. AI 문장은 텍스트로만 표시하고 HTML로 실행하지 않는다.
- 기존 모달은 닫기·직군 변경·초기화 시, 대시보드 자동 추천은 역할 입력 수정·동의 철회·직군 변경·초기화·로그아웃 시 진행 중 요청을 취소하고 늦은 응답은 무시한다. 결과 버튼은 현재 신청 상태를 다시 확인하는 기존 흐름을 사용한다.

## 검증

`node --test scripts/tests/ai-recommendation.test.cjs`는 43개 카탈로그, 직군+업무 케이스 예외 추천, 입력·출처 검증, 미설정 상태, 공급자 호출 규격, 후속 질문, 잘못된 출력·거절·실패 처리를 공급자 모의 응답으로 검증한다. 기존 `npm run quality`에서도 실행한다. 서버 테스트는 Playwright의 테스트 수집 경로 밖에 두어 브라우저 테스트와 섞이지 않게 한다.

대시보드 자동 추천의 동의/입력 대기/직군 외 요청/분류 탐색/이전 응답 무효화/신청 연결은 Playwright `tests/ai-inline.spec.js`에서 모의 API로 검사한다. 기존 화면의 시각 기준선은 새 영역을 제외하고 유지하며, 신규 영역은 별도 회귀 테스트로 점검한다. 실제 API 키를 사용한 추천 품질·응답 시간·비용과 데스크톱/모바일 화면·시각 회귀는 별도 검증 대상이다. 모의 공급자 테스트 통과를 실제 AI 연동 검증으로 표현하지 않는다.

### WebKit 검사 환경의 기존 오류

기준 main `8dfe984`의 E2E 실행 `39942527372`에서도 WebKit의 기본 직군 선택 상자가 `style-src-attr` 오류를 발생시켰다. Playwright 1.64.0/1.64.1의 WebKit 27.2에서 기본 select 내부 스타일이 CSP 검사에 걸리는 알려진 상위 엔진 오류다. 근거: https://github.com/microsoft/playwright/issues/43416

WebKit의 신청·승인 기능 검사 컨텍스트에만 공식 임시 대응인 `bypassCSP:true`를 적용한다. 실제 사이트의 CSP, Firefox 설정, Chromium 및 필수 Security 검사는 변경하지 않는다. 별도 WebKit 재현 검사는 CSP를 다시 켠 새 컨텍스트에서 앱 코드나 스타일 없는 select 하나로 같은 위반이 발생하는지 확인한다. 상위 오류가 해결되면 재현 검사가 실패하므로 임시 대응을 제거해야 한다. WebKit 기능 검사 성공을 WebKit의 CSP 검증 성공으로 해석하지 않는다.

## 사용자 검증 지표

기존 목록 탐색과 비교해 라이선스 선택 소요 시간, 추천 적합도, 추천 후 신청 전환율을 측정한다. 추천 라이선스 수나 신청 수 증가만을 성공으로 보지 않는다. 공통 지급 라이선스만으로 충분한 상황에서 추가 신청을 유도하지 않는지도 함께 평가한다. 개선 수치는 아직 측정하지 않았다.

공식 구현 참고: https://ai.google.dev/gemini-api/docs/generate-content/structured-output · https://vercel.com/docs/functions/runtimes/node-js

## Gemini 무료 등급 연결 순서

1. https://aistudio.google.com/api-keys 에서 Google 계정으로 로그인하고 프로젝트·API 키를 생성한다. 화면 안내에 따라 약관·프로젝트 생성을 완료한다.
2. 프로젝트가 Free Tier인지 확인하고 결제 계정을 연결하거나 유료 업그레이드를 하지 않는다. 모델별 실제 한도는 계정에서 확인한다.
3. Vercel Preview 환경변수에 `GEMINI_API_KEY`와 `AI_RECOMMENDATIONS_ENABLED=true`를 등록한다. 키를 소스·채팅에 넣지 않는다. 기존 OpenAI/Groq 키는 이 코드에서 사용하지 않는다.
4. 미리보기 재배포 후 실제 추천 품질과 한도 초과 안내를 확인한다. 키가 없으면 503 안내를 유지한다.

공식 무료 등급 안내: https://ai.google.dev/gemini-api/docs/pricing · https://ai.google.dev/gemini-api/docs/billing

## 추천 기반 신청 사유 초안
추천 결과에서 신규 신청 가능한 라이선스를 선택하면 담당 역할과 AI 추천 이유를 조합해 200자 이내 초안을 표시한다. 별도 AI 호출 없이 기존 결과를 재사용한다. 수정 후 확인란을 선택해야 제출할 수 있으며 수정하면 확인 상태가 해제된다. 취소한 초안은 다른 신청에 전달하지 않는다.

## 추천 API 요청 보호
같은 실행 인스턴스에서 이용자 IP를 비식별 키로 바꾸고 동시 1건, 분당 5건, 시간당 20건을 허용한다. 제한 시 429와 Retry-After를 반환하며 AI 호출 전에 차단한다. 실패·시간 초과·거절 후에도 동시 요청 잠금을 해제한다. 원본 IP나 입력 내용을 기록하지 않는다. Vercel에서는 플랫폼이 덮어쓰는 X-Forwarded-For를 사용하고, 다른 환경에서는 소켓 주소만 신뢰한다.

외부 저장소·유료 서비스를 추가하지 않는 메모리 기반 완화 장치다. 카운터는 콜드 스타트·배포 시 초기화되며 인스턴스 간 공유되지 않는다. 따라서 분산 환경의 절대 사용량 상한이나 인증 경계가 아니며, 공유 IP의 이용자는 같은 제한을 적용받는다. 전체 한도 보장이 필요하면 공유 저장소나 플랫폼 수준 제한을 별도로 도입해야 한다.

담당 역할을 편집하면 진행 중 응답과 기존 추천을 무효화하며, 다시 추천한 결과만 신청 초안에 전달한다. AI 결과에서 다른 모달로 이동할 때 최초 AI 추천 진입점의 포커스 정보를 전달한다.
